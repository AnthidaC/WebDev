# CAMPUS GEAR — สอบปฏิบัติ Full Stack

เวลา 4 ชั่วโมง · คะแนน 100 · React + Express · ข้อมูลจำลองบันทึกลงไฟล์ JSON

พัฒนาระบบยืมอุปกรณ์ของมหาวิทยาลัยจากเทมเพลตที่ให้มา ให้ผู้ใช้ค้นหาอุปกรณ์ ส่งคำขอยืม และติดตามสถานะ ส่วนผู้ดูแลจัดการรายการจองและคลังอุปกรณ์ ตัวอย่างหน้าตาอยู่ใน `reference/campus-gear-target.png` และเปิดดูหน้าอ้างอิงได้จาก `reference/index.html` โดยไม่ต้องต่ออินเทอร์เน็ต

## บัญชีและการเริ่มระบบ

- API: `http://localhost:3000`; React: `http://localhost:5173` (dev server มี proxy `/api` ให้แล้ว)
- บัญชีตัวอย่าง: `admin@campus.test`, `mali@campus.test`, `niran@campus.test`; รหัสผ่านทุกบัญชี `Campus123!`
- `npm install`, `npm run reset`, `npm run dev`; ตรวจด้วย `npm test`
- ปรับข้อมูลเริ่มต้นได้ด้วย `npm run reset`; ข้อมูลจริงเก็บใน `backend/data/db.json`
- อนุญาตให้เพิ่ม แก้ ย้าย และลบไฟล์ ใช้ React Router และแยก component ตามความเหมาะสม

## ข้อกำหนดและคะแนน

### R01 — โครงหน้าและการนำทาง · 8 คะแนน
สร้างหน้าหลัก, คลังอุปกรณ์, รายละเอียดอุปกรณ์, เข้าสู่ระบบ, สมัครสมาชิก, รายการยืมของฉัน, คิวผู้ดูแล และจัดการคลังอุปกรณ์ พร้อม header/sidebar, สถานะเมนู, หน้าจอ 404 และ layout ที่ใช้ได้บนมือถือ

### R02 — สมัครสมาชิกและเข้าสู่ระบบ · 10 คะแนน
สมัครด้วยชื่อ อีเมล และรหัสผ่านอย่างน้อย 8 ตัวอักษร; อีเมลไม่ซ้ำและปรับเป็นตัวพิมพ์เล็ก; hash รหัสผ่านด้วย bcrypt; login คืน JWT หมดอายุ; register ห้ามกำหนด role เอง; แสดงข้อผิดพลาดที่เข้าใจได้

### R03 — คลังและค้นหา · 8 คะแนน
`GET /api/equipment` รองรับ `search`, `category`, `availableOnly`, `sort`; รายละเอียด `GET /api/equipment/:id` รองรับช่วงวันที่และคืนจำนวนว่าง; id ที่ไม่มีอยู่คืน 404

### R04 — ตรวจช่วงวันและจำนวนว่าง · 12 คะแนน
ตรวจวันที่จริงและรูปแบบ `YYYY-MM-DD`, วันเริ่มไม่ย้อนหลัง, วันสิ้นสุดไม่น้อยกว่าวันเริ่ม, ยืมต่อรายการไม่เกิน 7 วัน; นับจำนวนที่จองซึ่งสถานะ pending/approved แล้วทุกวันในช่วง และคืนจำนวนว่างต่ำสุดของช่วงนั้น

### R05 — สร้างและดูรายการจอง · 12 คะแนน
ผู้ใช้เข้าสู่ระบบจึงจองได้; ตรวจ equipment, quantity จำนวนเต็มบวก, วันที่และ stock ซ้ำก่อนเขียนข้อมูล; ยอดมัดจำ = มัดจำต่อชิ้น × จำนวน; เริ่มที่สถานะ pending; ผู้ใช้ดูเฉพาะรายการของตนและกรองสถานะได้ (ผู้ดูแลดูทั้งหมด)

### R06 — ยกเลิกคำขอ · 8 คะแนน
เจ้าของยกเลิกได้เฉพาะรายการ pending/approved; คนอื่นได้ 403, รายการที่ไม่มีได้ 404 และสถานะปลายทางยกเลิกซ้ำไม่ได้; รายการยกเลิกคืน stock สำหรับการคำนวณ

### R07 — คิวผู้ดูแลและลำดับสถานะ · 10 คะแนน
เฉพาะ admin เปลี่ยน pending → approved/rejected และ approved → returned; การเปลี่ยนข้ามขั้นหรือสถานะที่ไม่รู้จักคืน 409; API ทุกจุดตรวจสิทธิ์ฝั่ง server

### R08 — จัดการอุปกรณ์ · 10 คะแนน
admin เพิ่ม/แก้/ลบอุปกรณ์; ตรวจชื่อ, รหัสไม่ซ้ำ, หมวด, stock 1–100, deposit ไม่ติดลบ; ลด stock ต่ำกว่ายอดจองที่ยัง active ไม่ได้ และลบอุปกรณ์ที่มีรายการ active ไม่ได้

### R09 — สรุปสำหรับผู้ดูแล · 5 คะแนน
แสดงจำนวนอุปกรณ์, stock รวม, รายการ active, คำขอ pending และยอดมัดจำของรายการ active โดยไม่รวม cancelled/rejected/returned

### R10 — เชื่อมหน้าเว็บครบ flow · 10 คะแนน
ค้นหา/กรอง/เรียง, ดูรายละเอียดและเช็ก stock ตามวันที่, สมัคร/เข้า/ออก, จอง, ดูและยกเลิกของตน, อนุมัติ/ปฏิเสธ/คืนของ, CRUD อุปกรณ์และสรุปผล ต้องเชื่อม API จริงพร้อมสถานะ loading/error/success/empty

### R11 — คุณภาพและส่งงาน · 7 คะแนน
ทดสอบกรณีสำเร็จและผิดพลาด, ใช้สถานะ HTTP ให้เหมาะสม, แยก route/controller/service, เก็บ secret ฝั่ง server, ส่ง README สั้น ๆ พร้อมวิธีรันและบัญชีตัวอย่าง, จัด CSS สม่ำเสมอและ responsive

## เงื่อนไขสำคัญสำหรับตรวจงาน

- ความพร้อมของ stock คิดเป็นช่วงวันที่แบบรวมวันเริ่มและวันสิ้นสุด; รายการซึ่งแตะวันเดียวกันถือว่าทับซ้อน
- การตรวจ stock และสร้าง booking ต้องเป็นการอัปเดตข้อมูลหนึ่งรอบโดยไม่มี `await` คั่นระหว่างเช็กกับบันทึก
- Error response เป็น JSON `{ "message": "..." }`; ห้ามส่ง passwordHash หรือ JWT secret ออกให้ client
- ระบบในชุดนี้ใช้ JSON store เพื่อให้รันได้ทันทีแบบ offline; ไม่ต้องติดตั้ง MySQL, Docker หรือ XAMPP
- พิจารณาคะแนนจาก requirement, การทดสอบกรณีขอบ และ README; ชุด `npm test` เป็นตัวช่วยฝึก ไม่ใช่ rubric ทั้งหมด
